# Changelog

All notable changes to this package are documented in this file.

## Unreleased

- New package, not published yet. `encryptEnvelope` and `decryptEnvelope` implement the `seed-private/v1` envelope described in `SPEC.md`: a header of recipient stanzas and a `bind` line, authenticated by an HMAC under the file key, and a payload of 64 KiB AES-256-GCM chunks whose first bytes hold the content type and body length. The plaintext is zero-padded to its PADMÉ length by default (at most 12% extra), so the envelope size shows a size class rather than the exact length; `padding: 'none'` turns that off. Decryption fails with an `EnvelopeError` whose `code` names the problem (`HEADER_MAC`, `TRUNCATED`, `BAD_CHUNK`, `TRAILING_DATA`, `BIND_MISMATCH`, ...).
- The `mlkem768x25519` recipient stanza: `generateRecipientKeyPair`, `wrapFileKey`, `unwrapFileKey` and `unwrapWithSecretKeys` seal the file key to an X-Wing public key with HPKE (KEM `0x647a`, HKDF-SHA256, AES-256-GCM), following age's construction. Adds `@noble/post-quantum` as a dependency.
- Encryption identity and keystore manifest. `createEncryptionIdentity` makes a 32-byte identity secret from which the recipient key, an X25519 tag key and a key id are derived. `generateRecoveryPhrase` and `recoveryKeyFromPhrase` handle a 24-word BIP39 recovery phrase. `buildKeystoreManifest` writes the public manifest (a `seed-private/v1` envelope holding the identity secret) with one stanza per authenticator: the recovery key, a passkey's PRF output (`passkey-prf`, with `enrollPasskey` and `passkeyPrf` for WebAuthn) or a deterministic EOA signature (`eoa-signature`). `openKeystoreManifest` unlocks it and checks the contents against the key id. `saveIdentityOnDevice` and `loadIdentityFromDevice` keep an unlocked identity in IndexedDB under a non-extractable key. Adds `@noble/curves` and `@scure/bip39` as dependencies.
- `registerEntitlementAdapter(kind, adapter)` and `isEntitled(policy, address, blockTag)`: one adapter per access-policy kind decides who may receive keys.
