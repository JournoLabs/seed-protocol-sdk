# Changelog

All notable changes to this package are documented in this file.

## Unreleased

- `createEnvelopeDecryptor(identities)` returns the decryptor for the SDK's `setEnvelopeDecryptor`: it opens an envelope wrapped to any of the identities' recipient keys and returns null when none is a recipient.
- `createPrivateUploadEncryptor({ recipients, bind, padding })` returns the `encryptPrivateUpload` for `@seedprotocol/publish`: each upload becomes its own envelope with a fresh file key and envelope id, wrapped to every recipient, its real content type inside and a `Seed-Encryption: seed-private/v1` tag outside. It needs only public keys.
- New package, not published yet. `encryptEnvelope` and `decryptEnvelope` implement the `seed-private/v1` envelope described in `SPEC.md`: a header of recipient stanzas and a `bind` line, authenticated by an HMAC under the file key, and a payload of 64 KiB AES-256-GCM chunks whose first bytes hold the content type and body length. The plaintext is zero-padded to its PADMÉ length by default (at most 12% extra), so the envelope size shows a size class rather than the exact length; `padding: 'none'` turns that off. Decryption fails with an `EnvelopeError` whose `code` names the problem (`HEADER_MAC`, `TRUNCATED`, `BAD_CHUNK`, `TRAILING_DATA`, `BIND_MISMATCH`, ...).
- The `mlkem768x25519` recipient stanza: `generateRecipientKeyPair`, `wrapFileKey`, `unwrapFileKey` and `unwrapWithSecretKeys` seal the file key to an X-Wing public key with HPKE (KEM `0x647a`, HKDF-SHA256, AES-256-GCM), following age's construction. Adds `@noble/post-quantum` as a dependency.
- Encryption identity and keystore manifest. `createEncryptionIdentity` makes a 32-byte identity secret from which the recipient key, an X25519 tag key, an Ed25519 binding key and a key id are derived. `signKeyBinding(identity, { account, chainId })` signs that the identity belongs to an account on a chain, and `verifyKeyBinding` checks such a signature; an account's encryption key registration carries it. `encryptionKeyId` and `keyBindingMessage` give the key id and the signed bytes SPEC.md defines. `generateRecoveryPhrase` and `recoveryKeyFromPhrase` handle a 24-word BIP39 recovery phrase. `buildKeystoreManifest` writes the public manifest (a `seed-private/v1` envelope holding the identity secret) with one stanza per authenticator: the recovery key, a passkey's PRF output (`passkey-prf`, with `enrollPasskey` and `passkeyPrf` for WebAuthn) or a deterministic EOA signature (`eoa-signature`). `eoaSignatureStanza` needs `acceptWalletKeyRisk: true` and throws `BAD_KEYSTORE` without it, because anyone with the wallet's key can then open the identity and read every private Version wrapped to it. `openKeystoreManifest` unlocks it and checks the contents against the key id. `saveIdentityOnDevice` and `loadIdentityFromDevice` keep an unlocked identity in IndexedDB under a non-extractable key. Adds `@noble/curves` and `@scure/bip39` as dependencies.
- `registerEntitlementAdapter(kind, adapter)` and `isEntitled(policy, address, blockTag)`: one adapter per access-policy kind decides who may receive keys.
